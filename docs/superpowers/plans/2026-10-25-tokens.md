# Item 2 — validação de tokens

Objetivo: rejeitar assinaturas inválidas e tokens malformados sem executar a operação protegida.

Contexto: o item 1 antecipou a exigência de `TJWT.Verified` e do algoritmo HS256. A biblioteca local `TJOSE.Verify` devolve o objeto também quando a verificação da assinatura retorna false. O item 2 amplia a regressão e corrige eventuais lacunas reproduzidas.

Arquitetura: manter a biblioteca criptográfica existente para ler a estrutura compacta e verificar a assinatura; consumir claims somente depois de assinatura HS256 confirmada. Manter compatibilidade com tokens emitidos pelo login atual.

- [x] Criar e executar testes HTTP com token válido, assinatura incorreta, assinatura ausente, payload/header adulterados, algoritmos indevidos e serializações malformadas.
- [x] Conferir lacunas em providers/Autenticacao.pas: a correção antecipada no item 1 já cobre os casos; nenhuma mudança adicional de produção necessária.
- [x] Executar suíte de tokens e regressão do item 1 em banco isolado, verificando ausência de mutações negadas.
- [x] Compilar o executável principal Win32/Debug.
- [x] Revisar a alteração: revisão independente sem achados bloqueadores.

Verificação: testes reais contra middleware/controllers compilados, com Conexao SQLite e chave fictícia. A suite existente verifica também token emitido pelo login real.

## Evidências em 25/10/2026

- Suíte de tokens: 30 verificações aprovadas. Cada token recusado retorna 401/CREDENCIAIS_INVALIDAS e não altera o telefone no banco fictício. Tokens HS256 válidos persistem a alteração antes e depois das tentativas inválidas.
- Regressão do item 1: 88 verificações aprovadas, incluindo token emitido pelo login real.
- Contraprova: cópia do middleware sem a condição `not LJWT.Verified` produziu 10 falhas nos 30 casos; assinaturas incorretas, ausentes ou truncadas passaram pela assinatura indevidamente. A cópia ficou restrita a tests/.build; o fonte de produção permaneceu intacto. A suíte completa foi recompilada e executada depois com o middleware correto.
- Build principal: MSBuild Build, Win32/Debug, sucesso; hints H2443 anteriores permanecem.
- Revisão independente confirmou os 28 casos de recusa e os dois controles válidos, a verificação de persistência e a propagação da falha pelo runner. A evidência da contraprova são as dez falhas funcionais registradas, incluindo respostas 200 com assinatura inválida; seu exit code isolado não seria prova suficiente.
- Comando reproduzível: powershell -NoProfile -ExecutionPolicy Bypass -File tests/run-authorization.ps1.
- Escopo: item 2 encerrado após revisão; item 3 (configuração externa de segredos) ainda não iniciado.
